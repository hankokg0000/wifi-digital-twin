# WiFi Digital Twin

Digital twin ของบ้านทั้งหลังที่ตรวจจับคนและการเคลื่อนไหวจาก **สัญญาณ WiFi** รวมถึงในห้องที่ไม่มีเซนเซอร์มองเห็นโดยตรง เพราะสัญญาณ WiFi วิ่งทะลุผนังห้องนั้น (Non-line-of-sight Detection) โดยคนในบ้านไม่ต้องพกอุปกรณ์ใดๆ (device-free WiFi Sensing)

โปรเจกต์เริ่มแบบ **sim-first** ทุกอย่างรันใน browser พร้อม simulator คนและสัตว์ เพื่อพัฒนาและวัดผลตัวตรวจจับให้เสร็จก่อนต่ออุปกรณ์จริง

## ทำอะไรได้แล้ว

- **Scene editor:** วาดผนัง ประตู หน้าต่าง ห้อง เฟอร์นิเจอร์ router และบันได บ้านหลายชั้นได้ save/load เป็น JSON มีบ้านตัวอย่าง 2 ชั้นมาให้
- **Simulator:** กดปุ่มเดียวสุ่มคนและสัตว์ให้เดินเองทั้งบ้าน (ขึ้นลงบันไดได้) สุ่มเหตุคนล้มได้ ลาก timeline ย้อนไปมาได้
- **พื้นที่ห้ามเข้า + การแจ้งเตือน:** แจ้งเมื่อมีคนบุกรุก, คนล้ม และคนล้มแล้วไม่ลุกเกิน 60 วินาที
- **WiFi heatmap สด:** โมเดลการลดทอนสัญญาณผ่านผนัง ประตู เฟอร์นิเจอร์ ตัวคน และพื้นระหว่างชั้น (2.4 / 5 GHz) คนเดินบังสัญญาณแล้ว heatmap เปลี่ยนตาม
- **UI แบบ ops console:** โหมด Monitor (ดูสถานการณ์) และ Edit (แก้ผัง)

**งานถัดไป:** Pilot ตรวจจับการเคลื่อนไหวผ่านผนังในห้องเดียว ด้วย router + Mac laptop ดูรายละเอียดใน [docs/HANDOFF.md](docs/HANDOFF.md)

## เริ่มใช้งาน

ต้องมี Node 24 และ pnpm

```bash
pnpm install
pnpm dev
```

คำสั่งเดียวเปิดทุกหน้าจากโปรเจกต์นี้

| หน้า | เปิดที่ |
|---|---|

| Indoor Twin | [อาคารและผังชั้น 14](http://localhost:5173/indoor-twin/) |

การอ่าน RSSI จริงใช้ Mac ที่เชื่อมกับ WiFi ตั้ง `RSSI_FAKE=1` ก่อนรัน `pnpm dev` เพื่อทดสอบด้วยสัญญาณจำลองในหน้า WiFi Digital Twin

| `pnpm e2e` | E2E test (Playwright) |

## Camera Twin

หน้า `/camera-twin/` ใช้ธีมของ WiFi Digital Twin และแสดงวิดีโอคู่กับผังออฟฟิศ 3D หน้า `/` เปิด WiFi Digital Twin

หน้า `/indoor-twin/` เปิดที่ฉากเมืองและอาคารกระจกโดยอ้างอิง [AIA Capital Center บนถนนรัชดาภิเษก](https://property.jll.co.th/en-th/aia-capital-center) รถและคนเดินในเมืองเป็นภาพจำลอง กดที่อาคารหรือ **เข้าชั้น 14** เพื่อเปิดแปลนสาธิต 10 พื้นที่ที่จัดรอบแกนลิฟต์ โดยอิงผังสำนักงานตัวอย่างของอาคาร กดพื้นที่บนผังเพื่อซูมเข้า และกด **ภาพรวมไซต์** เพื่อซูมกลับ ทุกพื้นที่มีวิดีโอและแผนวางเราเตอร์กับตัวรับ Wi-Fi ผังและตำแหน่งจากวิดีโอเป็นค่าประมาณ ห้องประชุมจับคู่สีของกรอบกับตัวคนนั่งที่เก้าอี้ในผัง ส่วนภาพที่ไม่มีจุดอ้างอิงจะแสดงกรอบในวิดีโอ

เข้าไปในห้องที่ต้องการบน Mac แล้วกด **ใช้วิดีโอใหม่** เพื่อวิเคราะห์คลิปจากกล้องมุมคงที่และเปิดผัง 3D ที่สร้างจากคลิปนั้น รองรับ MP4, MOV, WebM หรือ MKV ขนาดไม่เกิน 200 MB และยาวไม่เกิน 3 นาที เตรียมโมเดลครั้งแรกด้วย `pnpm camera:setup-scene` คลิปและผังที่อัปโหลดเก็บแยกตามห้องใน `.wdt-data/indoor-twin` บน Mac

เมื่อเข้าห้องบน Mac แผง **ตรวจจับ Wi‑Fi** เปิดอัตโนมัติและแสดงกราฟ RSSI (dBm) จาก Wi‑Fi ที่ Mac เชื่อมอยู่ กราฟใช้รูปแบบเดียวกับแผง **ตรวจจับ WiFi** ในหน้าหลักและแสดงข้อมูลย้อนหลัง 60 วินาที กด **ผูก RSSI กับห้องนี้** และ **บันทึก Baseline** ในช่วงที่พื้นที่นิ่ง 30 วินาทีเพื่อเปิดการตรวจจับบนผัง ห้องที่ผูกและ Baseline ที่บันทึกครบจะใช้ต่อหลังรีโหลดในเบราว์เซอร์เดิมเมื่อกลับมาอ่าน RSSI ที่ช่องเดิม ให้บันทึกใหม่เมื่อเปลี่ยนเครือข่ายหรือย้ายตัวรับ

สำหรับลิงก์ดูสด ให้ออกบิลด์ด้วย `VITE_INDOOR_WIFI_PUBLIC=1` และตั้ง `WDT_INDOOR_WIFI_PUBLIC_FILE` ตอนรันเซิร์ฟเวอร์บน Mac ให้ชี้ไปที่ไฟล์ `indoor-twin/live-wifi.json` ในไดเรกทอรีเว็บของลิงก์ที่แชร์ ลิงก์จะแสดง RSSI สดและสถานะของห้องที่ผูกไว้ เบราว์เซอร์บน Mac ใช้ผูกห้องและส่ง Baseline ที่บันทึกไว้ให้เซิร์ฟเวอร์ประเมินต่อได้ถึงแม้ปิดแท็บควบคุม

เมื่อเลือก **CSI** Indoor Twin รับข้อมูล จากชิป Wi‑Fi BCM43455c0 (เช่น Raspberry Pi 4B ที่ตั้งค่า [Nexmon CSI](https://github.com/seemoo-lab/nexmon_csi)) ในช่อง 20 MHz ผ่าน UDP โดยตรง ใช้เฟรม Wi‑Fi จากอุปกรณ์ที่ควบคุมได้ในเครือข่ายทดสอบ ตัวส่งและตัวรับควรอยู่คงที่

1. รันเซิร์ฟเวอร์ Indoor Twin บน Mac โดยตั้ง `WDT_CSI_UDP_HOST=<IP LAN ของ Mac>` และ `WDT_CSI_UDP_PEER=<IP LAN ของ Pi>` พอร์ตเริ่มต้น `5500` เปลี่ยนได้ด้วย `WDT_CSI_UDP_PORT` หากส่งจากโปรแกรมในเครื่องเดียวกัน ค่าเริ่มต้นฟังเฉพาะ `127.0.0.1:5500`
2. หลังเตรียมตัวรับตามคู่มือ Nexmon แล้ว ตั้งกรอง MAC ของตัวส่งที่ต้องการในตัวรับ หรือระบุ `WDT_CSI_WIFI_PEER=<MAC ของตัวส่ง Wi-Fi>` ที่เซิร์ฟเวอร์ ใช้ช่อง 20 MHz และหนึ่ง core/stream ตามคู่มือ ตัวรับส่ง payload UDP ของ Nexmon ไปที่ Mac ได้ เช่น ใช้ IP ของ Mac แทน `MAC_LAN_IP` ในคำสั่งบน Pi ที่เชื่อม LAN ผ่าน Ethernet: `socat -u UDP4-RECV:5500,reuseaddr UDP4-SENDTO:MAC_LAN_IP:5500`
3. ในแผง **ตรวจจับ Wi‑Fi** เลือก **CSI** แล้วกด **ผูก CSI กับห้องนี้** เมื่อกราฟมีข้อมูล ให้กด **บันทึก Baseline** ขณะพื้นที่นิ่ง 15 วินาที ระบบไฮไลต์ห้องสีฟ้าอมเขียวเมื่อความผันผวนถึงเกณฑ์การเคลื่อนไหว ตัวรับหนึ่งตัวผูกกับห้องได้ครั้งละห้อง ให้บันทึก Baseline ใหม่เมื่อย้ายอุปกรณ์ เปลี่ยนเครือข่าย หรือสัญญาณขาด ข้อมูลจริงเปิดได้บนเครื่องที่รันเซิร์ฟเวอร์

### เปิดเดโมออฟฟิศ

ถ้ามีไฟล์ `public/camera-twin/office-demo/replay.json` แล้ว เปิดเดโมออฟฟิศได้เลย ถ้ายังไม่มี ให้เตรียมคลิปบน Mac ที่มี FFmpeg และ Swift CLI tools แล้วจึงบิลด์

```bash
pnpm camera:prepare-demo "/path/to/office.mp4"
pnpm build
```

เปิด `/camera-twin/?demo=1` เพื่อเล่นคลิปกับผังออฟฟิศตัวอย่างทันที ปุ่มหยุดและแถบเลื่อนเวลาควบคุมทั้งวิดีโอและตัวคน 3D ตัวคนสีเขียวฟ้าแสดง **ตำแหน่งจำลองจากคลิป** เดโมจะเปิดจาก `/camera-twin/` ด้วยเมื่อยังไม่มีห้องที่เลือกใช้หรือคลิปที่เผยแพร่ ไฟล์คลิปและข้อมูลติดตามเก็บใน `public/camera-twin/office-demo/` บนเครื่องที่เตรียม และรวมอยู่ใน `dist/` หลังบิลด์

### อัปโหลดและเล่นย้อนหลัง

ใช้ Mac ที่มี FFmpeg, Swift CLI tools และ dependencies จาก `pnpm install` เปิดเว็บที่พอร์ตสำหรับทดสอบ

```bash
pnpm build
pnpm preview --host 127.0.0.1 --port 5189 --strictPort
```

เปิด `http://127.0.0.1:5189/camera-twin/` บน Mac เครื่องที่รันเดโม เลือก **ควบคุมคลิป → อัปโหลดคลิป** ใช้คลิป MP4, MOV, WebM หรือ MKV จากมุมกล้องออฟฟิศเดิม ขนาดไม่เกิน 200 MB และยาวไม่เกิน 3 นาที ตัวตรวจจับแปลงคลิปและบันทึกร่างไว้ใน `.wdt-data` บน Mac

ดูตำแหน่งคู่กับวิดีโอในร่าง แล้วกด **เผยแพร่ → ยืนยันเผยแพร่** เพื่อเปลี่ยนคลิปของผู้ชม ผู้ที่เปิดลิงก์จะเห็นวิดีโอจากคลิปที่เผยแพร่ ร่างเปิดได้จาก Mac ที่รันเดโม เวลาเล่นของผู้ชมอ้างอิงเซิร์ฟเวอร์ ปุ่มหยุดชั่วคราวมีผลเฉพาะหน้านั้น

### สร้างแปลนจากวิดีโอโดยอัตโนมัติ

เตรียมโมเดลบน Mac ครั้งแรกด้วย `pnpm camera:setup-scene` โดยใช้ Python 3.14 สำหรับตัวอ่านภาพ เปิด **ควบคุมคลิป** แล้วอัปโหลดโดยเลือก **สร้างแปลนจากวิดีโอ** สำหรับร่างที่อัปโหลดแล้ว ให้กด **สร้างแปลน 3D จากคลิปนี้** ระบบอ่านพื้น ผนัง และของหลักจากหลายช่วงของคลิป แล้ววางโมเดลเรขาคณิตในแปลนมุมสูง วิดีโอต้นฉบับแสดงคู่กันและการประมวลผลทำบน Mac

ใช้คลิปจากกล้องมุมคงที่และเห็นพื้นชัด ขนาดใช้สัดส่วนจากภาพ แนวพื้นและผนังที่เติมจะแสดงเป็นเส้นประ ส่วนรูปทรงสีเทาคือของที่เห็นแต่ยังแยกชนิดไม่ได้ จุดสีม่วงแสดงตำแหน่งที่อ้างอิงพื้นได้ กรอบสีเหลืองแสดงผลตรวจจับจากวิดีโอเมื่อยังวางตำแหน่งบนแปลนไม่ได้ ร่างคลิปจะเผยแพร่เมื่อยืนยันผ่านหน้าควบคุม

### สแกนห้องด้วยมือถือ

เปิด `/camera-twin/scan/` จาก Mac ที่รัน Camera Twin หลังเตรียมโมเดลด้วย `pnpm camera:setup-scene` เลือกคลิป MP4, MOV, WebM หรือ MKV ความยาว 6–90 วินาที ขนาดไม่เกิน 180 MB ถ่ายต่อเนื่องหนึ่งห้อง เดินช้า ๆ และให้เห็นพื้นชนผนังกับเฟอร์นิเจอร์จากหลายจุด

ระบบจับคู่ภาพเพื่อหาตำแหน่งกล้อง แล้วประมาณแนวพื้น ผนัง และวัตถุเป็นรูปทรง 3D เส้นประแสดงแนวที่ยังต้องถ่ายเพิ่ม เลือกประตูที่ตรวจพบเพื่อดูเฟรมอ้างอิงและใส่ความกว้างจริง ขนาดที่แสดงหลังปรับสเกลเป็นค่าประมาณ

หากต้องการถ่ายตรงจากมือถือ ให้ตั้ง `WDT_CAMERA_SCAN_ORIGIN` เป็น URL HTTPS ของ Camera Twin ที่มือถือเข้าถึงได้ก่อนเปิดเซิร์ฟเวอร์ จากนั้นเปิดหน้าสแกนบน Mac แล้วกด **สร้างลิงก์สแกนบนมือถือ** ลิงก์มีอายุหนึ่งชั่วโมงและเข้าถึงได้เฉพาะร่างจากลิงก์นั้น วิดีโอและแปลนเก็บบน Mac ใน `.wdt-data/room-scans` โดยแยกจากคลิป Camera Twin เดิม

กด **นำเข้า USDZ หรือ PDF** ในหน้าเดียวกันเพื่อเปิดไฟล์แปลนขนาดไม่เกิน 25 MB ใช้ `usdcat` บน Mac และ Poppler สำหรับ PDF รองรับโมเดลหนึ่งห้องจาก magicplan และแสดงรูปทรงพื้น ผนัง ช่องเปิด และเฟอร์นิเจอร์จากไฟล์ด้วยสีเรียบ ใช้ปุ่ม **ผนังโปร่ง** เพื่อสลับมุมมองให้เห็นภายในห้อง ถ้ามี Sketch PDF ของห้องเดียวกัน กด **เทียบสเกลด้วย PDF** เพื่อใช้ขนาดจากแปลน ระบบตรวจสอบรูปทรงก่อนบันทึกสเกล

เมื่อเลือก Sketch PDF หนึ่งห้องจาก magicplan เว็บแสดงหน้าแรกและสร้างแนวพื้นกับผนังจากแปลน สำหรับ PDF รุ่นอื่นหรือที่เป็นภาพสแกน เว็บจะแสดงตัวอย่างหน้าแรก

### ใช้คลิปจากมุมใหม่ของห้องเดิม

เลือก **มุมใหม่ของห้องเดิม** ก่อนอัปโหลด หรือเปิดร่างเดิมแล้วกด **ปรับเทียบมุมกล้อง** ใช้คลิปจากกล้องที่อยู่กับที่ เลือกจุดบนพื้นในวิดีโอแล้วคลิกตำแหน่งเดียวกันบนผังมุมบน ทำจนครบ 4 คู่ เรียงจุดรอบพื้นที่โดยเว้นระยะและให้เส้นไม่ตัดกัน

กด **พรีวิวมุมใหม่** เพื่อลองเล่นวิดีโอและเช็กตำแหน่งในผัง 3D แล้วกด **บันทึกผัง** การปรับเทียบผูกกับคลิปนั้น ส่วนผังห้องออฟฟิศใช้ฉากเดิม คลิปที่เลือกมุมใหม่จะแสดงผลตรวจจับในวิดีโอได้ระหว่างรอปรับเทียบและต้องบันทึกก่อนเผยแพร่

### วาดเขตและวางเก้าอี้ในผัง

ใน **ควบคุมคลิป** กด **วาดเขตติดตาม** แล้ววางอย่างน้อย 3 จุดตามแนวพื้นบนวิดีโอ เขตสามารถครอบคลุมบริเวณโต๊ะและทางเดินที่อยู่ในผัง กด **ปิดเขตและพรีวิว** แล้วลองเล่นคลิปเพื่อดูผลติดตามในเขตใหม่

เตรียมโมเดลตรวจเก้าอี้จาก Apple บน Mac ครั้งแรกด้วย `pnpm camera:setup-chairs` จากนั้นหยุดคลิปที่เฟรมที่เห็นเก้าอี้แล้วกด **ค้นหาเก้าอี้ในเฟรมนี้** ระบบตรวจที่เครื่องและแสดงผลบนภาพกับผัง 3D เลือก **ใส่ในผัง** แล้วใช้ **ขยับ** หรือ **ลบ** ได้ ตำแหน่งอิงจุดใกล้พื้นของกรอบที่ตรวจพบ เก้าอี้ในผังเป็นโมเดลตัวแทนแบบอยู่กับที่

กด **บันทึกผัง** เพื่อเก็บเขตและเก้าอี้ในร่าง ก่อนแชร์ให้กด **เผยแพร่ → ยืนยันเผยแพร่** ผู้ชมจะเห็นฉบับล่าสุดที่ยืนยันเผยแพร่แล้ว

ถ้ากล้องเห็นช่วงบนแต่ยืนยันจุดอ้างอิงบนพื้นไม่ได้ วิดีโอจะแสดงกรอบตรวจจับสีเหลือง ผังจะแสดง **ตำแหน่งล่าสุด** ได้ประมาณครึ่งวินาที หรือซ่อนตำแหน่งเมื่อไม่มีจุดอ้างอิง สำหรับร่างคลิปที่อัปโหลดก่อนเพิ่มการตรวจช่วงบน ให้กด **วิเคราะห์การติดตามใหม่** จากหน้าควบคุม โปรแกรมจะบันทึกเฉพาะผลติดตามของร่างนั้น

สำหรับทดสอบข้อมูลตำแหน่งอย่างเดียว คำสั่ง `pnpm camera:prepare "/path/to/office.mp4" 26.5 8` จะใช้ช่วงวินาทีที่ 26.5 ยาว 8 วินาทีเป็น Replay สำรองเมื่อยังไม่มีคลิปที่เผยแพร่

### รับภาพจากกล้อง Wi-Fi

ตั้ง `WDT_CAMERA_RTSP` เป็น URL สตรีมของกล้องที่ Mac เข้าถึงได้ และ `WDT_CAMERA_CALIBRATION` เป็นพาธไฟล์การปรับเทียบ จากนั้นเปิด `pnpm preview` อีกครั้ง กล้องต้องอยู่มุมคงที่และใช้พื้นที่ที่อนุญาตให้ใช้กล้อง

ไฟล์การปรับเทียบมี `image` และ `floor` อย่างละ 4 คู่พิกัดเรียงรอบพื้นที่ติดตาม โดยจุดลำดับเดียวกันต้องตรงกัน `image` ใช้พิกัด 0–1 วัดจากมุมซ้ายบนของภาพขนาด 960×540 หลังย่อและเติมขอบรักษาสัดส่วน `floor` ใช้พิกัด `[x, z]` ในผัง ฉากเดโมนี้แสดงผังออฟฟิศจากคลิป การนำไปใช้กับสถานที่อื่นต้องใช้ฉากและจุดปรับเทียบของที่นั้น

### ใช้แปลนที่นำเข้ากับคลิป กล้องสด และ ESP32

เปิดหน้าสแกน `/camera-twin/scan/` ตรวจพรีวิว USDZ หรือ Sketch PDF แล้วกด **ใช้ห้องนี้** จากนั้นใช้หน้า `/camera-twin/` บน Mac เพื่ออัปโหลดคลิปเดโมมุมคงที่ เลือก **คลิปเดิม** เพื่อกลับไปดูฉากเดิม

- **กล้องสด** ให้ตั้ง `WDT_ROOM_CAMERA_RTSP` เป็น URL RTSP ของกล้อง แล้วเปิดเซิร์ฟเวอร์ Camera Twin ใหม่ ใช้ **กล้องสด** ในหน้าเว็บ เมื่อห้องมีสเกลเป็นเมตร ให้พิมพ์ **แผ่นอ้างอิง A4** แนวนอนที่ 100% วัดเส้นทดสอบให้ครบ 100 มม. ตัดขอบ วางแผ่นราบกับพื้นโดยให้ขอบ A–B ชิดผนังและตัวอักษรตรงกับไกด์ กด **เริ่มอ่านแผ่น** เมื่อเห็น QR ครบทั้งสี่ช่องในภาพ ใช้มุมติดตั้งอื่นได้ผ่าน **ลองมุมถัดไป** เก็บแผ่นได้หลังเว็บยืนยัน และตั้งกล้องใหม่เมื่อย้ายกล้อง เปลี่ยนซูม หรือเปลี่ยนมุม
- **Wi-Fi จำลอง** กด **จำลองการเคลื่อนไหว** เพื่อทดสอบการไฮไลต์ทั้งห้อง ข้อมูลจะมีป้าย **จำลอง**
- **ESP32 ผ่าน USB** ใช้บอร์ดที่รันเฟิร์มแวร์และส่งบรรทัด `CSI_DATA` อยู่แล้ว โดยให้ Mac เป็นโปรแกรมที่อ่านพอร์ตเพียงตัวเดียว แอปเลือกพอร์ต USB serial อัตโนมัติเมื่อมีหนึ่งพอร์ต หรือระบุ `WDT_ESP32_PORT` เช่น `/dev/cu.usbserial-0001` ค่าเริ่มต้น 115200 baud รองรับ 230400 ผ่าน `WDT_ESP32_BAUD` ถ้าบอร์ดรายงานหลายแหล่ง ให้ระบุ MAC ของอุปกรณ์ส่งสัญญาณของห้องใน `WDT_ESP32_PEER` แล้วเลือก **ESP32 ผ่าน USB** และกด **บันทึกช่วงห้องนิ่ง** เมื่อเว็บรับข้อมูลแล้ว ให้ตั้งช่วงห้องนิ่งใหม่หากอุปกรณ์หรือเครือข่ายเปลี่ยน
- ขณะเล่นคลิปเดโม กรอบบนวิดีโอและตัวคนสีเขียวฟ้าบนแปลนเปลี่ยนตามเฟรมเดียวกัน ตัวคนมีป้าย **ตำแหน่งจำลองจากคลิป** และอิงสัดส่วนจากภาพกับรูปทรงพื้น กล้องสดแสดงพิกัดเมื่อปรับเทียบสำเร็จ ระบบแสดง Wi-Fi เป็นสถานะระดับห้อง ภาพและการตั้งค่าห้องที่เลือกใช้ได้จาก Mac ที่รันเว็บ

## โครงสร้าง

```
src/core/   pure TypeScript ไม่มี React/three ทดสอบใน Node ได้
  scene/    data model, validate, ops, serialize/parse, บ้านตัวอย่าง
  sim/      navgrid, A*, agent planner, populate
  alerts/   คำนวณการแจ้งเตือน
  rf/       propagation model, heatmap, room coverage
src/ui/     React + react-three-fiber + zustand
e2e/        Playwright
docs/       เอกสารออกแบบ
```

**Stack:** Vite · React 19 · TypeScript · three.js / @react-three/fiber · zustand · Web Worker (comlink) · vitest · Playwright

## หลักการออกแบบ

- **World ≠ Twin:** World คือความจริง (ใน sim) ส่วน Twin คือสิ่งที่ระบบประมาณจากเซนเซอร์ ตัวตรวจจับห้ามอ่านตำแหน่งจริง
- **เซนเซอร์เสมือนเหมือนของจริง:** ตัวตรวจจับใช้ชุดเดียวกันทั้งกับข้อมูลจำลองและข้อมูลจริง
- **ผลซ้ำได้:** ทุกอย่างที่สุ่มใช้ seeded PRNG ใช้ doc + seed เดียวกันได้ผลเดิมเสมอ
- **ของจริงต้องติดป้าย:** ผลจากเซนเซอร์จริงแสดงคู่กับสิ่งที่จำลองได้ แต่ต้องมีป้าย "ของจริง" ชัดเจน
